# Network Traffic Analysis Using Wireshark

## Project Overview

This project focuses on analysing network traffic using **Wireshark** to understand network communication patterns and investigate potentially unusual TCP and DNS behaviour.

A packet capture containing approximately **25,197 packets** was examined using Wireshark display filters. The analysis focused on DNS queries and responses, TCP retransmissions, duplicate acknowledgements, fast retransmissions, SYN requests, and TCP reset packets.

## Objectives

- Capture and inspect network traffic using Wireshark.
- Understand TCP communication and DNS resolution.
- Identify retransmissions, duplicate ACKs, and TCP reset packets.
- Use Wireshark display filters to investigate network behaviour.
- Document observations and potential network reliability issues.

## Tools Used

- **Wireshark** – Network protocol analyser
- **Windows** – Operating environment
- **TCP/IP and DNS** – Protocols investigated

## Analysis Performed

### 1. DNS Query and Response Analysis

**Display filters:**
```text
dns
dns.flags.response == 0
dns.flags.response == 1
```

**Observations:**
- Examined DNS queries generated by the local system.
- Investigated a DNS lookup for `www.msftncsi.com`.
- Observed a DNS response with the status `No error`.
- The response contained four answer records, including CNAME and A records.

**Finding:** The observed DNS lookup completed successfully, demonstrating the process of domain resolution.

### 2. TCP Retransmission and Duplicate ACK Analysis

**Display filters:**
```text
tcp.analysis.retransmission
tcp.analysis.duplicate_ack
tcp.analysis.fast_retransmission
```

**Observations:**
- Identified TCP retransmission packets in the capture.
- Observed duplicate acknowledgements indicating that the receiver was acknowledging previously received sequence data.
- Identified a fast retransmission involving a 66-byte TCP segment.
- Examined packet sequence numbers, acknowledgement numbers, and TCP flags.

**Finding:** These observations indicate TCP recovery and reliability mechanisms. Retransmissions and duplicate ACKs can occur due to packet loss, packet reordering, or network congestion. They do not independently confirm a security attack.

### 3. TCP SYN Requests and Connection Reset Analysis

**Display filters:**
```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
tcp.flags.reset == 1
```

**Observations:**
- Identified TCP SYN packets initiating connections to remote services.
- Observed connection attempts involving HTTP (port 80) and HTTPS (port 443).
- Identified a TCP RST packet, which is used to reset or terminate a TCP connection.
- Examined source and destination ports and TCP flags.

**Finding:** SYN packets are part of normal TCP connection establishment. A reset packet indicates that a connection was reset, but further investigation would be required to determine its cause.
